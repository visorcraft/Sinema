Review of the multi-server profile feature:

**Bugs**
1. **Crash on malformed URL** (`SettingsActivity.kt:68`): `java.net.URI(prefs.serverUrl).host` throws `URISyntaxException` if the server URL is malformed (e.g., missing scheme, invalid chars). No try/catch — app crashes when returning from SetupActivity.
2. **Data inconsistency on legacy save** (`SettingsActivity.kt:336-340`): The "Save Settings" button updates legacy prefs (`serverUrl`, `apiKey`) but does **not** update the active profile in `prefs.profiles`. Edits are lost on the next profile switch or app restart because the profile list still holds the old values.

**Security**
- No new security issues. Credentials continue to live in `EncryptedSharedPreferences`. Profile list is serialized to secure prefs. OK.

**Anti-patterns**
- `requireActivity().recreate()` is used 4× (add server, rename, remove). On Android TV this causes visible flicker and can race with the fragment lifecycle. Prefer targeted UI updates or `notifyDataSetChanged`-style refresh.

**TV UX**
3. **Long-press is inaccessible on TV remotes** (`SettingsActivity.kt:271-274`): `setOnLongClickListener` for profile options (Rename/Remove) is a TV anti-pattern — most D-pad remotes don't reliably generate long-press events. Users may be unable to rename or remove servers. A dedicated "Options" button per row (or a click-to-show dialog) is the standard TV pattern.
4. **No cancel path in add-profile mode** (`SetupActivity.kt:36-44`): When launched with `"add_profile"`, pressing Back loops to the menu screen instead of cancelling. There is no button to return `RESULT_CANCELED`, trapping the user in SetupActivity.

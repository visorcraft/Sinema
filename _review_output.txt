## Review Findings

**1. Migration idempotency / atomicity bug** — `Prefs.kt:76-77`
`profiles = listOf(p)` (secure prefs) and `activeProfileId = p.id` (plain prefs) are two separate `apply()` calls. If the process crashes between them, `profiles` is non-empty but `activeProfileId` is blank. On next launch `migrateToProfilesIfNeeded()` returns early because `profiles.isNotEmpty()`, leaving `activeProfile` permanently null. **Fix:** set `activeProfileId` before `profiles` so a crash allows re-migration, or add a safety-net check for `activeProfileId.isBlank() && profiles.isNotEmpty()`.

**2. Profile list read-modify-write race** — `SinemaApp.kt:42-44`
`onSessionRefreshed` reads `prefs.profiles`, maps, and writes back. If the API invokes this on a background thread (common for network callbacks), it races with main-thread profile mutations (rename, remove, settings save). One update can silently clobber another. **Fix:** dispatch the profile list update to the main thread, or synchronize/serialize all profile mutations.

**3. Gson does not respect Kotlin default values** — `ProfileCodec.kt:8`, `ServerProfile.kt:5`
Plain Gson instantiates Kotlin data classes via reflection/UnsafeAllocator; missing JSON fields may become `null` rather than using Kotlin default parameter values. The `id` field is especially critical—if null, profile matching and switching will NPE. The test `partial json fills defaults` does not assert `id`. **Fix:** use `kotlinx.serialization` (which respects defaults) or validate/deserialize through a no-arg DTO.

**4. Settings save diverges when active profile is missing** — `SettingsFragment.kt:277-288`
If `activeProfileId` is stale/corrupted and `activeProfile` returns null, the save button updates legacy prefs but skips updating the profile list. The next profile switch will restore stale values. **Fix:** handle the null case (e.g., recreate the active profile from legacy prefs, or assert).

**5. TV D-pad focus order** — `ServerProfileSection.kt:49-113`
Each profile row is a horizontal `LinearLayout` with two focusable `Button`s. Pressing DOWN on the main profile button may move focus to the "..." button instead of the next row, creating a zig-zag navigation pattern. **Fix:** set `nextFocusDown` / `nextFocusUp` explicitly on the row buttons.

**6. TV AlertDialog focus visuals** — `ServerProfileSection.kt:71, 117`
`AlertDialog.Builder(ctx).setItems(...)` and `.setPositiveButton`/`.setNegativeButton` use the system default theme, which on some Android TV devices provides poor or invisible focus highlighting for list items and buttons. **Fix:** use a leanback-styled dialog or a custom layout with clearly focusable buttons.
